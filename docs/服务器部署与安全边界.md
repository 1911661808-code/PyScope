# 服务器部署与安全边界

本说明对应带登录和 Docker 任务后端的服务器模式。安装入口与示例文件见 [deploy/README.md](../deploy/README.md)。当前没有用户服务器信息，本说明和模板不代表已在腾讯云或其他生产服务器完成部署。

## 1. 推荐结构

服务器应用使用专用非 root 账户运行，通过 Waitress 提供一个进程、多个请求线程。任务由该账户专供本实例的 rootless Docker 启动，镜像为本地构建的 `pyscope-worker:1.1.0`。应用后台只监听 `127.0.0.1:9000`，浏览器入口选择 SSH 隧道或 HTTPS 反向代理。数据目录由进程锁独占；Docker daemon 不与其他实例或业务共用。

Waitress 的单进程多线程模型符合当前会话保存在内存中的设计；不能增加多个 WSGI worker 或随意启动第二个应用实例，否则请求可能落到不持有该执行会话的进程。Waitress 本身不处理 TLS。[Flask 的 Waitress 部署说明](https://flask.palletsprojects.com/en/stable/deploying/waitress/)、[Waitress 反向代理说明](https://docs.pylonsproject.org/projects/waitress/en/latest/reverse-proxy.html)

服务器必须显式配置密钥、密码哈希和允许的浏览器来源，没有通用初始密码。初始化时输入密码，不把明文密码写进命令行、Git、环境示例或 systemd unit。服务器模式使用 Docker 后端；Docker、镜像、必需的资源限制或指定 runtime 不可用时，应拒绝启动，不改用宿主机本地执行。

## 2. 不用域名如何访问

自己使用时选择 SSH 隧道，在本机终端执行：

```bash
ssh -N -L 127.0.0.1:18765:127.0.0.1:9000 用户@服务器公网IP
```

浏览器访问 `http://localhost:18765`。允许来源配置必须精确包含该地址，不能随便换成其他端口、主机名或通配符。HTTP 只出现在本机回环和服务器回环段，中间传输受 SSH 保护。此模式的 cookie 非 Secure 例外只用于显式配置的回环来源；不要把配置复用为公网 HTTP 登录。安全组使用既有 SSH 规则，不开放后台 9000 或本机 18765。

公网 IP 也可以作为 HTTPS 入口，但证书必须包含相应 IP 的 SAN，且访问端实际信任其签发链；也可使用已由访问端明确信任的内部 PKI。不能把“浏览器点忽略证书错误”当作完成 TLS 部署。公网入口强制 Secure cookie，允许来源应为精确的 `https://公网IP` 或实际 HTTPS 主机名。[OpenSSH 本地转发](https://man.openbsd.org/ssh#L)、[腾讯云安全组说明](https://www.tencentcloud.com/document/product/213/15377)

## 3. rootless Docker 的前提

rootless 指 Docker daemon 和容器均在非 root 用户下运行；把普通用户加入 rootful Docker 的 `docker` 组不等同于 rootless。官方安装要求包含用户命名空间、`newuidmap`/`newgidmap` 以及分配给专用账户的 subordinate UID/GID。Docker daemon 应作为该账户的 systemd 用户服务管理。[Docker rootless 模式](https://docs.docker.com/engine/security/rootless/)

必须确认 cgroup v2、systemd cgroup driver 及 memory、pids、cpu 控制器有效委派。rootless 环境不满足条件时，Docker 可能忽略相关限制参数。因此不仅要看启动命令中是否出现限制，还要验证启动检查与真实任务的实际限制；失败时不要删掉限制参数继续上线。[Docker rootless 资源限制](https://docs.docker.com/engine/security/rootless/tips/#limiting-resources)

Docker CLI 和 socket 只属于宿主应用控制通道。任务容器不得挂载 Docker socket、应用数据目录、源码目录、登录配置或 TLS 密钥，不传入宿主秘密环境变量。镜像名、runtime 和启动参数只能来自受信任的部署配置，不能由提交代码的请求指定。能控制 daemon 的账户仍能管理其容器和可访问的宿主文件，应使用专用账户并隔离其他业务。[Docker daemon 的攻击面说明](https://docs.docker.com/engine/security/#docker-daemon-attack-surface)

## 4. 任务与网络边界

每次调试或性能分析需要独立任务容器，并按实现施加只读根文件系统、非 root 容器用户、禁用网络、移除 capabilities、禁止提权、临时可写目录、内存/CPU/进程数与执行时间上限。宿主服务还需要限制并发和请求大小，避免大量合法的小任务合起来耗尽资源。部署验收应同时检查停止、超时、异常、退出后的容器清理，不能只用正常样例判断隔离有效。

标准 Docker 提供操作系统级容器隔离，但仍共享宿主 Linux 内核；配置错误、内核和 runtime 漏洞仍可能突破边界。登录限制访问，不能把提交的代码变成可信代码，也不意味着同一账户下不同浏览器之间具备租户隔离。当前系统面向受控账户，不能表述为匿名任意代码公网执行平台的安全承诺。

建议在目标主机条件允许时配置 gVisor 的 `runsc` runtime，进一步缩小任务直接接触宿主内核的接口。必须按 rootless Docker 的实际架构安装与验证；不要照搬 rootful `/etc/docker/daemon.json` 或直接添加不适合 Docker 的 `runsc --rootless` 参数。若配置指定 `runsc` 而目标主机没有可用 runtime，应拒绝启动，不静默回落为 `runc`。[gVisor Docker 接入](https://gvisor.dev/docs/user_guide/quick_start/docker/)、[gVisor rootless 模式](https://gvisor.dev/docs/user_guide/rootless/)

## 5. 反向代理与凭据

HTTPS 模板仅把请求转发到回环的 9000，后端不能另行绑定公网地址绕过 TLS。入口的 Host 与来源应匹配实际证书地址；拒绝未知 Host。当前 Waitress 清除未配置为可信的转发头，认证依赖部署配置的精确来源与 Host；同机反代后的来源 IP 限流会合并为每 5 分钟 15 次，成功尝试也计数，另有用户名与全局限流。模板覆盖客户端传来的转发链并清除不使用的 `Forwarded`。若以后启用代理头解析，只信任明确配置的本地代理，不能把任意网络来源设为可信。增加 CDN 或负载均衡时需要重新核对整条代理链与限流行为。[Waitress 代理参数](https://docs.pylonsproject.org/projects/waitress/en/stable/arguments.html#trusted-proxy)、[Nginx 代理头说明](https://nginx.org/en/docs/http/ngx_http_proxy_module.html#proxy_set_header)

真实配置、密码哈希、会话签名密钥、运行数据库和证书私钥不提交到仓库。备份按敏感文件管理：历史记录含用户源码、变量和输出。换密钥可能使现有登录失效，更新密码或清除记录前应由管理员确认预期影响。

## 6. 实际上线前的证据

模板提供部署步骤，不替代目标主机验收。至少记录：Docker rootless 与资源控制检查、镜像与源码版本、拒绝缺失 runtime、未登录访问限制、错误密码与登录节流、CSRF/来源拒绝、cookie 属性、SSH 或 HTTPS 的真实浏览器登录、任务无法访问宿主秘密和外网、资源超限终止、容器清理、历史读写及服务重启。

2026 年 10 月 12 日，GitHub Actions 的 Ubuntu 24.04 环境中，rootless Docker 29.9.0 + systemd cgroup v2 的 70 项检查全部通过，包括真实服务器 CLI/Waitress 登录、调试、性能、AST、历史、注销与 SIGTERM 容器清理。[本次 CI](https://github.com/1911661808-code/PyScope/actions/runs/38227212251) 的具体范围见 `服务器版验证.json`。这不代表用户腾讯云主机已经部署；目标服务器、gVisor、systemd 应用 unit、Nginx 与公网 TLS 仍需在目标环境验收。
