# PyScope 界面设计说明

本次界面优化以用户提供的《网页与界面设计参考及可复用提示词》为设计参考，围绕代码执行、状态观察和结果解释调整工作台。本文记录参考如何转化为本项目的设计规则；实现与验收结论以实际代码、截图和后续验证记录为准。

## 1. 任务与视觉方向

PyScope 属于需要反复操作和比较数据的开发工具。主要路径是选择或输入代码、开始调试、观察当前状态，再通过对象关系、调用栈、AST、性能统计和历史记录解释结果。因此采用数据导向工作台：保持编辑器与状态区域的稳定位置，将常用执行控制放在源码附近，把示例与历史归入工作空间。

界面的视觉重点来自真实执行数据。代码行、对象节点、调用栈和时间轴共同表达同一时刻，避免装饰抢占程序内容。保留既有深色画布和青绿色品牌识别，用有限的表面层级、分隔和字重组织信息。

## 2. 参考到项目规则的转化

| 参考原则 | PyScope 的设计规则 | 应检查的真实内容 |
| --- | --- | --- |
| 密度服从任务，统一对齐轴 | 编辑、执行控制和状态分析形成连续工作区；数字和表格列共享对齐规则 | 递归的多层调用栈、对象列表、函数性能表 |
| 中文需要独立调校 | 主要中文正文采用 13–14 px，辅助说明约 12 px；长标题自然换行，避免用大字距分隔中文 | 示例标题、错误说明、中英文标识符混排 |
| 色阶承担稳定角色 | 分开画布、面板、边界、主要文字、辅助文字、强调、警告和错误 | 运行、暂停、异常、禁用以及当前选中状态 |
| 响应式需要重排 | 窄屏将工作空间收为可打开的抽屉，保留新建、全部示例、历史和帮助入口；内容区按任务顺序重排 | 手机宽度下选择示例、运行程序、查看历史 |
| 状态与焦点可辨认 | 除颜色外保留状态文字、选中标记和可见焦点；标签页及对象节点提供键盘操作路径 | 标签切换、对象详情、抽屉关闭后的焦点返回 |
| 动效解释变化 | 只保留短暂的操作反馈；减少动态效果偏好下关闭非必要动画和过渡 | 面板切换、对象选择、抽屉与时间轴回放 |

Ant Design 的字体文档将 14 px 字号与 22 px 行高作为中后台主字号建议，并建议数字比较使用 `tabular-nums`。本项目据此选择适合代码工作台的中文尺寸与数字对齐，而不是引入整套 Ant Design 组件或把该数值当作所有区域的统一标准。[参考：Ant Design 字体](https://ant.design/docs/spec/font-cn/)

## 3. 信息层级与状态表达

顶层区分工作空间、主要工作内容和全局状态。源码编辑与运行控制保持紧密关联，变量和对象信息放在当前执行状态下，时间轴与输出用于回看执行证据。AST 与性能分析使用各自面板，避免把静态结构统计误当成运行次数。

字号、留白和字重共同表达层级。标题需要能够快速定位，辅助信息可以降低视觉强调，但不依靠极小字号维持布局。文件名、长标识符和错误文本应根据内容采用换行或局部滚动；不能通过遮住溢出内容隐藏操作入口。

语义色阶分别表达可操作、选中、警告和异常，并配合文字说明。默认空状态应解释当前缺少什么，以及可采取的下一步；运行中、执行完成、运行异常和载入历史需要能被清楚区分。历史快照仍是记录回放，界面不能暗示它撤销了真实程序的外部副作用。

## 4. 键盘与窄屏交互

标签页遵循明确的标签组模型：进入标签组时落在当前标签，左右方向键在标签间移动，Home 与 End 定位首尾；标签、面板、选中状态和焦点位置保持一致。是否随焦点自动激活，应结合该面板是否能即时展示内容决定。上述规则来自 WAI-ARIA APG 的标签页模式，实际采用方式与检查结果另行记录。[参考：WAI-ARIA APG Tabs Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/)

对象节点的交互不能只有鼠标点击。可操作节点应有可理解的名称、可见焦点和键盘激活行为，详情应显示对象身份与属性。抽屉打开与关闭需要清楚的触发入口，关闭后焦点返回合理位置；覆盖页面的抽屉还需要避免键盘焦点落入被遮挡的背景内容。

窄屏保留完整的工作空间入口，并对工具条、状态面板和主要内容重新排列。代码、对象关系图与性能表可能需要局部横向滚动；应控制在其自身区域，不让整页形成不必要的横向溢出。移动设备检查覆盖主要操作路径，而不只检查一张静态首页。

## 5. 方法参考的采用范围

Vercel Web Interface Guidelines 用于检查可见焦点、语义控件、空状态、长内容和 `prefers-reduced-motion` 等具体实现方法。该文件中的命令格式、英文文案习惯和其他与本项目不相关的条款不作为本次任务指令，也不代表本项目采用了该文件的全部规则。[参考：Vercel Web Interface Guidelines](https://github.com/vercel-labs/web-interface-guidelines/blob/main/command.md)

用户提供的参考还强调“用真实内容与截图复查”。本次因此需要保留递归、循环引用、AST 和性能的实际运行截图，用来检查视觉层级是否帮助解释程序状态。图片替换应与当前软件一致，正式报告和答辩文稿不使用设计稿冒充运行结果。
